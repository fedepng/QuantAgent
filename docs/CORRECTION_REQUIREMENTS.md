## 2. 审查结论

项目已经是一个**可以安装、启动、演示且具备自动化测试的本地 MVP**，但尚不能认定为“功能完善”。主流程已连通，17 个现有测试全部通过，依赖检查和 Python 编译检查也通过；不过，现有测试主要覆盖正常路径，没有覆盖若干会直接影响研究结论可信度的边界条件。

当前最重要的问题不是增加新因子、新数据源或更复杂的策略，而是：

1. 修正风险指标、回测会计和横截面因子的计算口径；
2. 收紧 CSV 与 API 输入校验，保证错误可解释且不会以 500 暴露；
3. 使数据、代码版本和 Agent 工具轨迹真正可追溯；
4. 清除页面加载即写入回测记录、硬编码演示股票等不必要行为；
5. 让 README、需求文档和实际能力保持一致。

完成本文 P0 后，可将项目描述为“结果口径明确、核心链路可复现的研究演示工具”；完成 P1 后，可将其描述为“较完善的本地单用户量化研究工作台”。本文不建议把它描述为生产级回测或交易系统。

## 3. 已验证事实

### 3.1 已正常工作的能力

- Windows 启动脚本、FastAPI 服务、原生 Web 页面和 Swagger 已接通；
- CSV 原始文件与标准化 Parquet 分离保存，数据集可切换并在正常情况下重启恢复；
- 五类既有因子、Top-K 回测、风险摘要、净值及回撤序列可以运行；
- Responses 与 Chat Completions 两种工具调用协议都有模拟测试；
- 工具使用白名单和 Pydantic 参数校验，不提供任意代码执行或交易指令；
- SQLite 能保存数据集、Agent 任务和回测结果；
- 当前测试结果为 `17 passed`，`pip check` 与 `compileall` 均通过。

### 3.2 已复现的缺陷

| 编号 | 现象 | 影响 |
|---|---|---|
| DEF-001 | 收益序列 `[-20%, +10%]` 的最大回撤被计算为 `0` | 风险指标错误，首日亏损被忽略 |
| DEF-002 | 不同股票数据结束日不一致时，同一次因子排名返回不同日期的值 | 结果不是同一时点的横截面，排名不可比 |
| DEF-003 | 同一股票同一自然日的 `00:00` 与 `12:00` 两行会同时通过导入 | 绕过 `date + symbol` 唯一性约束 |
| DEF-004 | `high=inf` 的行情可以通过导入校验 | 因子、回测和 JSON 输出可能出现非有限数 |
| DEF-005 | `/api/market/prices?start_date=not-a-date` 返回 HTTP 500 | 客户端输入错误被误报为服务端故障 |
| DEF-006 | Web 页面每次加载都会自动执行并持久化一次默认回测 | 刷新页面污染历史记录并产生无意义写入 |
| DEF-007 | 页面“行情查询”快捷按钮固定查询 `ALPHA` | 切换真实数据集后通常立即失败 |

## 5. P0：正确性修正需求（2.0.1）

### CR-P0-001 风险指标必须使用初始净值基线

**问题**：净值从第一条收益直接开始累计，回撤的历史峰值中没有初始净值 `1.0`，因此首日亏损不会形成回撤。

**需求**：

- 计算净值和回撤时显式加入初始净值 `1.0`；输出日序列时可以不输出额外日期，但计算基线必须存在；
- 最大回撤、净值曲线和每日回撤必须使用同一实现，禁止分别计算后产生差异；
- 明确夏普比率口径。建议采用 `日均超额收益 / 日收益标准差 × sqrt(252)`，无无风险利率输入时按 0 处理；
- 对空序列、单点序列、零波动、净值小于等于 0 和非有限收益给出明确结果或受控错误，禁止产生复数、`NaN` 或 `Infinity` JSON；
- VaR、CVaR、胜率和年化口径写入方法说明。

**验收标准**：

- `[-0.20, +0.10]` 的最大回撤为 `-0.20`；
- 第一日收益为负时，当日回撤等于该负收益；
- API 返回的 metrics 与 series 中的净值、回撤可以相互推导；
- 增加确定性单元测试覆盖上述边界。

### CR-P0-002 明确并修正回测执行与组合会计

**问题**：当前实现把缺失收益填为 0、目标权重在持有期内不随价格漂移、按完整日期索引决定调仓、先裁剪数据再计算窗口，并可能在结果裁剪时丢掉首次建仓成本。这些行为会使换手、费用和绩效失真。

**需求**：

- 在方法说明中固定信号时点、成交时点和收益区间。建议：使用 T 日收盘后信号，在 T+1 日可成交价格建仓，随后计算持有收益；若仍使用 close-to-close，必须明确其可交易假设；
- 调仓前权重应按上一期资产收益漂移，再与目标权重比较计算交易量；
- 建仓、换仓和最终是否平仓的成本规则必须明确，交易成本不得因结果区间裁剪而丢失；
- `start_date` 表示绩效统计起点。因子所需的预热行情应从起点之前读取，不得简单裁掉后再计算；
- 调仓序列从首个有效信号/可成交日开始计数，不应受原始 DataFrame 第 0 行位置影响；
- 不得无提示地将持仓股票缺失收益填为 0。至少区分“该日非全市场交易日”“股票停牌/缺价”“新上市历史不足”；
- 数据不足以完成预热或形成首次持仓时返回 422 和结构化原因；
- 方法说明返回实际首个信号日、首个持仓日、有效交易日数、跳过的股票/日期统计。

**验收标准**：

- 人工构造 2 至 3 只股票、5 至 10 个交易日的手算用例，逐日核对权重、换手、费用、收益和净值；
- 改变请求起点但保留相同预热数据时，共同统计区间的信号一致；
- 初次建仓成本只扣一次且不会被裁剪丢失；
- 缺失价格策略有测试，且 API/结果中可见采用的处理规则；
- 未来日期价格变化不影响此前权重与净值的现有测试继续通过。

### CR-P0-003 因子排名必须是同日横截面

**问题**：当前对每只股票分别取最后一个非空因子值，可能把不同日期的数据放在同一排名中。

**需求**：

- 因子快照先确定一个唯一 `as_of_date`，再仅使用该日有有效值的股票进行排名；
- 默认 `as_of_date` 为所选区间内、满足最小覆盖率的最后共同研究日；覆盖率规则必须固定并返回；
- 返回值顶层包含 `as_of_date`、请求股票数、有效股票数和排除原因；每一排名项日期必须相同；
- 若有效股票不足以形成横截面，返回 422，不得混用历史日期补齐；
- `reversal` 当前固定使用 5 日窗口，而接口仍接收 `lookback`。必须二选一：让反转因子使用请求窗口，或移除/重命名对该因子无效的参数并在 UI 中固定显示 5 日。建议统一使用请求窗口，减少隐藏规则；
- 低波动因子采用负波动值以便降序排序的实现可以保留，但响应必须同时给出 `raw_value`、`score` 和 `direction`，避免把负数误读为实际波动率。

**验收标准**：

- 任一因子排名中的所有记录日期相同；
- 股票结束日不一致的复现用例不再产生混合日期；
- 对每个现有因子验证窗口参数、排序方向和数值定义；
- 页面明确显示“截至日期”和有效股票覆盖数。

### CR-P0-004 收紧行情数据契约

**问题**：日期未归一为自然日，股票代码未去除首尾空格，非有限数未拒绝，错误信息也没有完整满足原需求中的行号、字段、原值和原因。

**需求**：

- 列名先去除首尾空格再统一小写；转换后若出现重复列名，拒绝导入；
- `date` 只接受可解释的无时区交易日期，统一归一到自然日后再检查 `date + symbol` 唯一性；
- `symbol` 执行 trim、uppercase，并拒绝空字符串、`nan` 字符串和超长值；
- OHLCV 必须是有限数；OHLC 大于 0、volume 大于等于 0；明确 volume 是否允许小数；
- 拒绝额外无法识别的数据造成的列冲突，但允许保留明确登记的可选列；
- 校验错误返回结构化数组，每项至少包含 CSV 行号、字段、原值和原因；一次最多返回约定数量并给出总错误数；
- 50 MB 限制必须在读取请求体时生效，不能读取完整文件后才判断；
- 标准化 Parquet 写入成功、数据库元数据写入成功和启用状态更新应具有一致的失败回滚/恢复策略。

**验收标准**：

- 同一自然日不同时间的重复记录被拒绝；
- `NaN`、`Infinity`、空 symbol、带空格 symbol、重复大小写列均有测试；
- 非法文件返回 422 和统一错误对象，不产生数据集目录或数据库记录；
- 合法 UTF-8 与 UTF-8 BOM 文件均可导入。

### CR-P0-005 API 错误必须统一且可诊断

**问题**：行情接口日期是未校验字符串，非法值会触发 500；其他接口混用 FastAPI 默认错误体和纯文本 `detail`，与原需求声明的统一错误响应不一致。

**需求**：

- 所有日期参数使用同一请求模型，校验格式和 `start_date <= end_date`；
- 统一错误格式：`code`、`message`、`details`、`request_id`；
- 参数错误、未知股票、数据不足、数据文件损坏、模型未配置、上游模型失败分别映射稳定错误码；
- 500 只用于未预期服务端错误，日志记录堆栈，对客户端不暴露路径、密钥或内部异常；
- `market/prices` 在日期范围无数据时，应区分“股票不存在”和“股票存在但区间无数据”。

**验收标准**：

- `start_date=not-a-date` 返回 422 而不是 500；
- 所有公开 API 的错误响应符合统一 Schema；
- OpenAPI 文档列出主要错误码；
- 增加 API 错误契约测试。

### CR-P0-006 可复现信息必须真实而非占位值

**问题**：回测 `code_version` 固定写为 `2.0.0`，不是实际 Git 提交；数据哈希是原始文件字节哈希，未明确它与标准化数据版本的关系。

**需求**：

- 回测保存实际 Git commit；无法取得时保存构建版本和明确的 `unknown` 状态，不得伪装成代码版本；
- 同时保存 `raw_file_hash` 与 `normalized_data_hash`，回测引用后者；
- provenance 增加数据集名称、复权方式、因子定义版本、风险指标口径版本；
- 数据集启用前校验 Parquet 是否存在、可读且哈希一致；恢复失败不得静默清空当前数据集并退回模拟数据，应在健康检查和页面中显示降级原因；
- SQLite 中 `backtest_runs.dataset_id` 建立可验证的引用关系，历史回测引用的数据版本不得被无提示替换。

**验收标准**：

- 任一历史回测可确定其标准化数据哈希和代码提交；
- 修改原始 CSV 的换行符但得到相同标准化数据时，两个哈希的语义可清楚区分；
- 删除或损坏活动 Parquet 后，启动状态明确为 degraded，而不是看似正常地使用模拟数据。

### CR-P0-007 Agent 工具轨迹必须完整且避免重复存储

**问题**：原需求声明保存逐次工具耗时、结果摘要和错误，但当前数据库只有任务级 `plan_json` 与完整 `result_json`；工具失败时也没有独立轨迹。Agent 结果中还可能再次保存完整回测序列，与 `backtest_runs` 重复。

**需求**：

- 每次工具调用独立记录 round、call_id、工具名、已校验参数、开始/结束时间、耗时、状态、结果摘要、错误码和关联回测 ID；
- Agent 任务结果只保存回答、调用引用和必要摘要；完整回测序列仅保存在 `backtest_runs`，避免重复大对象；
- 工具参数 JSON 非法、未知工具、参数校验失败、工具运行失败和模型失败均应保留已完成轨迹；
- 模型最终回答必须引用实际数据集、日期和回测 ID；若模型没有做到，服务端增加确定性元数据区，不依赖提示词保证；
- 对模型发送的回测输出继续使用摘要，不发送完整时间序列，以控制 token 和隐私暴露。

**验收标准**：

- 多轮成功、第二轮工具失败、模型超轮次三种任务都能还原完整执行过程；
- Agent 任务记录不再重复保存完整回测 series；
- 工具耗时和错误在 `/api/tasks/{id}` 中可查询；
- 两种 LLM 协议的现有测试继续通过，并增加失败轨迹测试。

## 6. P1：完整性与维护性修正需求（2.0.2）

### CR-P1-001 Web 页面不得产生隐式写入

- 删除页面初始化时自动调用 `runBacktest()` 的行为；初始页只加载健康状态、数据集列表和最近一次已有结果（若有）；
- 执行回测、因子、导入和 Agent 时禁用对应按钮并防止重复提交；
- 请求完成或失败后恢复按钮状态；
- 页面刷新不得新增回测记录。

### CR-P1-002 去除真实数据流程中的演示代码硬编码

- “行情查询”快捷操作应从当前数据集动态选择股票，或要求用户选择股票；
- `/api/market/prices` 不再默认 `ALPHA`，`symbol` 设为必填；
- 演示股票代码只允许存在于演示数据生成器与演示测试夹具中；
- 切换数据集后重置或校验页面中已填写的股票代码。

### CR-P1-003 补齐现有页面承诺，不新增产品模块

- 数据导入成功后展示已有 `quality` 内容，而不是只展示行数和股票数；
- 回测结果展示已有的全部风险指标、实际日期、数据集和方法说明；
- 显示当前持仓与最近换手，这些数据已经存在于 series，不新增后端能力；
- 从已有 `/api/backtests` 恢复历史摘要，满足原文档“刷新后恢复历史回测”的声明；
- 图表处理 0、1 个数据点和窗口 resize；坐标至少显示起止日期与数值范围。

### CR-P1-004 存储路径和启动恢复应可迁移

- 数据库不应只保存机器相关的绝对 Parquet 路径；优先保存相对 dataset root 的受控路径；
- 项目目录整体移动后，数据集仍能恢复；
- 启动时执行数据集元数据与文件完整性检查，并在 `/health` 返回 `ok/degraded`；
- 为 SQLite schema 引入显式版本迁移，替代仅在启动时零散 `ALTER TABLE`。

### CR-P1-005 收敛冗余和死代码

- 删除未使用的 `MarketDataService.replace_from_csv`，或证明其仍是受支持入口并添加测试；
- 评估并移除无调用方的兼容别名 `DeepSeekResearchAgent`；若保留，标注废弃版本和移除计划；
- 清理未使用导入和重复的结果计算；风险指标与回测序列必须共享净值/回撤实现；
- `plan` 与 `steps` 不应各自复制相同参数和大结果；采用调用 ID 引用；
- 保留 `run.bat` 与 `run.ps1`：两者分别服务 CMD 和 PowerShell，不视为无意义重复。

### CR-P1-006 限制本地服务暴露面

- 本地默认仅监听 `127.0.0.1` 的行为保留；
- 移除 `allow_origins=["*"]`，默认只允许同源；确需跨域时通过配置显式启用；
- 健康检查不得返回密钥，错误日志不得记录 API Key 或完整模型请求头；
- 增加基本安全回归测试。

## 7. 测试修正需求

现有 17 个测试保留，并至少补充以下类别：

| 类别 | 必测场景 |
|---|---|
| 数据契约 | 时间重复、空/带空格股票、非有限数、重复列、BOM、超限文件、失败无残留 |
| 因子 | 同日快照、异步结束日、窗口语义、低波动方向、有效覆盖不足 |
| 回测 | 手算权重漂移、首次建仓成本、部分换仓、缺价、预热期、破产/极端收益 |
| 风险 | 首日回撤、单点、零波动、全正/全负、非有限输入、metrics/series 一致性 |
| API | 非法日期、反向区间、未知股票、区间无数据、统一错误 Schema |
| 数据恢复 | 项目移动、Parquet 缺失/损坏、哈希不一致、degraded health |
| Agent | 工具参数错误、工具失败、模型失败、超轮次、轨迹耗时与错误持久化 |
| Web | 页面刷新无新增回测、切换真实数据后无 ALPHA 硬编码、重复点击保护 |

建议为核心计算设置分支覆盖目标，而不是只追求全项目行覆盖：

- `app/quant/`：分支覆盖不低于 90%；
- `app/datasets.py` 与 `app/tools.py`：分支覆盖不低于 85%；
- API 与 Agent 适配层：关键成功/失败路径全部有测试。

CI 在现有 pytest 之外增加：代码格式/静态检查、依赖完整性检查和测试覆盖阈值。是否增加类型检查可在修复实施时评估，不作为阻塞项。
