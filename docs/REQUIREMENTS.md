# QuantAgent 2.0 重构需求文档

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | QuantAgent 量化研究智能体 |
| 目标版本 | 2.0 |
| 文档状态 | 初稿 |
| 目标用户 | 量化研究学习者、策略研究人员、面试项目演示者 |
| 部署形态 | 本地单用户 Web 应用，预留服务化扩展能力 |

## 2. 项目背景

重构前版本已经实现自然语言 Agent、因子分析、横截面回测、风险指标和 SQLite 任务审计，但行情层仍以启动时生成的六个虚拟资产为主。真实 CSV 读取函数未接入启动流程和 Web 界面，股票代码被写死在参数模型及工具 Schema 中，回测结果也没有记录所使用行情数据的版本。

本次重构的核心不是增加更多展示功能，而是建立一条可验证、可追溯的真实研究链路：

> 导入行情 → 校验并持久化 → 选择数据集和股票池 → 计算因子 → 执行回测 → 展示风险 → 保存数据版本与工具轨迹。

## 3. 产品目标

### 3.1 核心目标

1. 支持用户通过 CSV 导入真实股票日线 OHLCV 数据，并在服务重启后继续使用。
2. 支持多个行情数据集、动态股票代码和可配置股票池，移除 `ALPHA` 等硬编码限制。
3. 保证 Agent 只负责理解需求与编排工具，所有行情、因子、回测和风险数值均由确定性程序计算。
4. 让每次研究结果都能追溯到数据集、数据版本、策略参数、工具调用和程序版本。
5. 将数据、领域计算、Agent、持久化和接口层解耦，为后续增加行情供应商和新策略提供稳定边界。

### 3.2 成功标准

- 用户无需修改 Python 代码即可完成 CSV 导入、股票池选择、因子分析和回测。
- 导入新股票代码后，API、页面和 Agent 工具均能自动识别。
- 使用相同数据版本和参数重复回测时，关键指标完全一致。
- 页面展示的参数、指标和净值曲线与数据库保存结果一致。
- 任一回测结果都可以明确回答“用了哪份数据、什么时间范围、哪些股票和什么参数”。

## 4. 范围定义

### 4.1 本期范围

- CSV 日线行情导入、校验、预览、持久化和切换；
- 数据集与股票池管理；
- 行情查询、五类现有因子、横截面 Top-K 回测；
- 风险指标、净值曲线、回撤曲线、持仓及换手展示；
- 可配置模型服务的多轮工具调用，支持 Responses 与 Chat Completions 两种协议；
- 任务、数据版本和回测结果审计；
- 模拟数据演示模式和自动化测试。

### 4.2 暂不纳入本期

- 实盘交易、券商下单和自动执行；
- 分钟级、Tick 级和实时行情；
- 多用户权限、团队协作和云端账户体系；
- 参数寻优、机器学习训练和自动挖掘因子；
- 对未来收益作保证或生成个性化投资建议。

## 5. 用户角色与典型场景

### 5.1 研究用户

- 上传一份包含多只股票的历史日线 CSV；
- 查看数据质量、时间范围和可用股票；
- 创建股票池并选择因子参数；
- 手动回测或使用自然语言要求 Agent 回测；
- 查看绩效、风险、持仓、换手和数据来源；
- 重新打开历史任务并复核结果。

### 5.2 演示用户

- 在没有真实数据和 API Key 时使用固定随机种子的演示数据；
- 演示确定性工具、Agent Function Calling 和审计链路；
- 运行不消耗真实模型额度的自动化测试。

## 6. 功能需求

优先级定义：P0 为重构必须完成，P1 为首个可用版本建议完成，P2 为后续扩展。

### 6.1 行情数据管理

| 编号 | 优先级 | 需求 |
|---|---|---|
| DATA-001 | P0 | 支持上传 UTF-8 CSV，字段至少包含 `date`、`symbol`、`open`、`high`、`low`、`close`、`volume`。 |
| DATA-002 | P0 | 字段名大小写不敏感，日期统一转换为交易日期，股票代码统一为字符串并转为大写。 |
| DATA-003 | P0 | 校验必填字段、类型、重复日期与股票、价格正数、成交量非负，以及 `low <= open/close <= high`。 |
| DATA-004 | P0 | 校验失败时返回行号、字段、原值和原因；任何错误都不得导致部分数据入库。 |
| DATA-005 | P0 | 保存数据集名称、市场、复权方式、来源、导入时间、起止日期、股票数量、记录数和内容哈希。 |
| DATA-006 | P0 | 行情必须持久化；服务重启后不得自动退回模拟数据或丢失当前选择。 |
| DATA-007 | P0 | 支持列出数据集、查看摘要、设为当前数据集和查询股票列表。 |
| DATA-008 | P1 | 支持在明确确认后删除非当前数据集，并阻止删除仍被历史回测引用的数据版本。 |
| DATA-009 | P1 | 支持增量导入，相同 `date + symbol` 可配置为拒绝或覆盖，并生成新的不可变数据版本。 |
| DATA-010 | P1 | 支持导出标准化后的行情 CSV。 |
| DATA-011 | P2 | 通过独立 Provider 接口接入外部行情源，Provider 不得与因子和回测代码耦合。 |

### 6.2 CSV 数据契约

标准输入示例：

```csv
date,symbol,open,high,low,close,volume
2024-01-02,000001.SZ,9.28,9.42,9.21,9.36,85213600
2024-01-03,000001.SZ,9.35,9.51,9.30,9.47,76325100
2024-01-02,600519.SH,1680.00,1695.00,1672.10,1688.50,2813500
```

数据规则：

- 一个文件允许包含多只股票，采用一行一只股票一个交易日的长表结构；
- 同一数据版本中 `date + symbol` 必须唯一；
- OHLC 必须采用同一种复权口径，禁止在同一数据集中混合不复权、前复权和后复权数据；
- 缺失交易日可以存在，但必须在数据质量报告中统计；
- 停牌日缺失收益的处理方法必须由回测配置明确，不能无提示地假设为正常成交；
- 原始上传文件与标准化数据应分别保存，便于审计和复现。

### 6.3 股票池管理

| 编号 | 优先级 | 需求 |
|---|---|---|
| UNIV-001 | P0 | 股票代码从当前数据集动态获取，Pydantic 模型和 Agent 工具中不得写死代码枚举。 |
| UNIV-002 | P0 | 支持选择全部股票或显式指定一组股票执行因子分析和回测。 |
| UNIV-003 | P0 | `top_k` 上限根据有效股票池动态校验。 |
| UNIV-004 | P1 | 支持保存、命名、查看和复用股票池。 |
| UNIV-005 | P1 | 回测时记录实际参与计算的股票列表，不能只记录股票池名称。 |

### 6.4 行情与因子研究

| 编号 | 优先级 | 需求 |
|---|---|---|
| FACT-001 | P0 | 支持查询指定股票和时间范围的 OHLCV 行情。 |
| FACT-002 | P0 | 保留动量、短期反转、低波动、均线偏离和成交量 Z-Score 五类因子。 |
| FACT-003 | P0 | 因子计算接口必须接收数据集版本、股票池、起止日期、因子名称和回看窗口。 |
| FACT-004 | P0 | 因子排名必须返回因子日期、股票代码、原始值、方向和排名。 |
| FACT-005 | P1 | 页面展示因子分布、排名表以及指定股票的因子时间序列。 |
| FACT-006 | P1 | 因子定义通过注册表管理，新因子不应要求修改 Agent 主循环。 |

### 6.5 回测与风险

| 编号 | 优先级 | 需求 |
|---|---|---|
| BT-001 | P0 | 回测参数至少包括数据集版本、股票池、起止日期、因子、回看窗口、持仓数量、调仓间隔和交易成本。 |
| BT-002 | P0 | 当日收益只能使用前一交易日或更早可用的信号，防止未来函数。 |
| BT-003 | P0 | 横截面 Top-K 策略采用等权持仓，并按权重变化计算换手率和单边交易成本。 |
| BT-004 | P0 | 返回累计收益、年化收益、年化波动、夏普、最大回撤、Calmar、VaR、CVaR、胜率和平均换手率。 |
| BT-005 | P0 | 保存每日收益、净值、回撤、换手率和持仓权重。 |
| BT-006 | P0 | 回测结果必须记录数据版本哈希、实际股票列表、参数、计算时间和代码版本。 |
| BT-007 | P1 | 支持配置基准序列并展示策略与基准净值对比。 |
| BT-008 | P1 | 对股票停牌、上市不足、退市、缺失价格和无法成交情况提供明确处理规则和统计。 |
| BT-009 | P1 | 支持从页面导出回测摘要 JSON/CSV。 |

### 6.6 Agent 能力

| 编号 | 优先级 | 需求 |
|---|---|---|
| AGENT-001 | P0 | 通过协议适配层支持 Responses API 与 Chat Completions Function Calling，并编排受控研究工具。 |
| AGENT-002 | P0 | Agent 只负责意图识别、参数补全、工具选择和结果解释，不得自行计算或编造金融指标。 |
| AGENT-003 | P0 | 用户显式参数优先；未指定时采用统一默认值：动量、20 日回看、Top-2、每 5 日调仓、5 bps。 |
| AGENT-004 | P0 | 工具参数执行前必须通过 Pydantic 二次校验，未知工具、股票和越界参数必须拒绝。 |
| AGENT-005 | P0 | 每次工具调用保存轮次、工具名、参数、耗时、结果摘要和错误信息。 |
| AGENT-006 | P0 | 限制最大工具轮数、输入长度和可调用工具集合；不得提供任意 Python、Shell 或交易工具。 |
| AGENT-007 | P0 | 数据集未选择、数据不足或参数冲突时明确说明，不得静默切换到演示数据。 |
| AGENT-008 | P1 | 最终回答引用数据集名称、版本、区间和回测编号，并使用 Markdown 结构化输出。 |
| AGENT-009 | P1 | 模型不可用时，手动行情、因子和回测功能仍可使用。 |

### 6.7 Web 研究面板

页面至少包含以下区域：

1. **数据管理**：上传 CSV、导入进度、质量报告、数据集列表、当前数据集和股票数量。
2. **研究任务**：自然语言输入、显式参数、Agent 运行状态、工具轨迹和 Markdown 回答。
3. **因子分析**：因子、窗口、股票池、日期选择及排名结果。
4. **策略回测**：参数表单、执行状态、错误说明和历史记录。
5. **风险概览**：指标卡、净值曲线、回撤曲线、当前持仓和换手情况。

界面要求：

- 所有指标必须标明单位和计算口径；
- 明确区分演示数据与真实数据；
- Markdown 输出必须转义原始 HTML 后渲染；
- 长任务显示执行中、成功或失败状态，禁止按钮无反馈；
- 移动端可读，表格允许横向滚动；
- 浏览器刷新后仍能恢复当前数据集和历史回测。

## 7. API 需求

建议的核心接口如下，最终路径允许在技术设计阶段微调：

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/datasets/import` | 上传并导入 CSV 数据集 |
| `GET` | `/api/datasets` | 查询数据集列表 |
| `GET` | `/api/datasets/{id}` | 查询数据摘要和质量报告 |
| `POST` | `/api/datasets/{id}/activate` | 设置当前数据集 |
| `GET` | `/api/datasets/{id}/symbols` | 查询动态股票列表 |
| `GET` | `/api/market/prices` | 按数据集、股票和区间查询行情 |
| `POST` | `/api/factors/analyze` | 执行因子分析 |
| `POST` | `/api/backtests` | 执行确定性回测 |
| `GET` | `/api/backtests/{id}` | 查询完整回测结果 |
| `GET` | `/api/backtests` | 查询历史回测列表 |
| `POST` | `/api/agent/run` | 执行 Agent 研究任务 |
| `GET` | `/api/tasks/{id}` | 查询 Agent 任务和工具轨迹 |

统一错误响应至少包含：

```json
{
  "code": "DATASET_VALIDATION_FAILED",
  "message": "CSV 数据校验失败",
  "details": [],
  "request_id": "..."
}
```

## 8. 数据与持久化设计要求

### 8.1 存储边界

- SQLite 保存数据集元数据、当前选择、股票池、任务、文档、工具轨迹和回测摘要；
- 标准化大规模 OHLCV 行情优先保存为 Parquet，按照数据集版本管理；
- 完整回测时间序列可保存为压缩 JSON 或 Parquet，数据库保存索引和摘要；
- 原始 CSV 只读保存，文件名必须由系统生成，禁止直接使用用户上传路径。

### 8.2 核心实体

- `datasets`：数据集及当前版本；
- `dataset_versions`：哈希、数据范围、复权方式和质量报告；
- `instruments`：数据版本中的股票元数据；
- `universes` / `universe_members`：命名股票池；
- `backtest_runs`：回测参数、指标和数据版本引用；
- `tasks` / `tool_calls`：Agent 任务及逐轮工具轨迹；

### 8.3 可复现性

任何研究结果都必须携带：

- `dataset_version_id` 与内容哈希；
- 实际股票列表；
- 起止日期与复权方式；
- 全部策略参数；
- 程序版本或 Git commit；
- 创建时间及结果编号。

## 9. 重构架构要求

项目按职责拆分为以下模块：

```text
app/
  api/              FastAPI 路由、请求模型和错误映射
  agent/            模型客户端、协议适配、提示词和工具循环
  application/      数据导入、研究任务和回测用例编排
  domain/           行情、因子、组合、回测和风险领域逻辑
  infrastructure/   SQLite、Parquet、文件存储和外部 Provider
  static/           Web 研究面板
```

约束：

- FastAPI 路由不得直接操作 Pandas DataFrame 或拼装 SQL；
- 领域层不得依赖 FastAPI、模型 SDK 或具体数据库；
- Agent 工具调用应用层用例，不直接访问内部对象；
- 外部行情源、模型和向量库均通过接口注入；
- 应用启动不得隐式创建或切换真实数据集。

## 10. 非功能需求

### 10.1 性能

- 50 MB 以内 CSV 导入时显示明确进度或处理中状态；
- 在普通个人电脑上，500 只股票、5 年日线的单因子回测目标耗时不超过 10 秒；
- 行情查询与历史回测列表的常规 API P95 目标不超过 500 ms；
- 大结果不得完整发送给模型，只传递指标、参数、最近观测和必要摘要。

### 10.2 安全

- 模型 API Key 仅从环境变量读取，不进入数据库、日志、接口响应和 Git；
- 上传文件限制扩展名、MIME、大小和解析耗时，防止路径穿越和资源耗尽；
- 模型文本在页面渲染前转义 HTML；
- Agent 仅能调用白名单工具；
- 删除数据和覆盖版本需要显式确认；
- 日志不得记录密钥、完整敏感文件内容或请求头。

### 10.3 可靠性与可观测性

- 数据导入和数据库写入使用事务，失败后不得留下半成品；
- 每个 API 请求生成 `request_id`，错误日志可据此定位；
- Agent、行情源或向量库失败时返回可理解的错误信息；
- 健康检查分别报告数据库、当前数据集、向量索引和模型配置状态。

### 10.4 兼容性

- Python 3.11 及以上；
- Windows 为首要运行环境，同时兼容 Linux/macOS；
- 启动方式保留 `run.bat`，PowerShell 脚本作为可选方式；
- Chrome、Edge 等现代浏览器可正常使用。

## 11. 测试要求

### 11.1 单元测试

- CSV 类型、价格关系、重复行、缺失值和复权口径校验；
- 五类因子公式与方向；
- 信号滞后一日和未来数据隔离；
- 调仓、权重、换手和交易成本；
- 全部风险指标；
- 动态股票池和数据版本哈希。

### 11.2 集成测试

- CSV 导入、持久化、重启恢复和数据集切换；
- 数据集 → 因子 → 回测 → 保存 → 查询完整链路；
- Agent 多轮 Function Calling、参数校验、错误恢复和审计；
- API 错误码及事务回滚。

### 11.3 前端验收

- 上传错误能显示具体原因；
- 动态股票列表与当前数据集一致；
- Markdown 标题、表格、列表和加粗正确渲染；
- 页面指标与回测 API 返回一致；
- 模型或网络不可用时，手动回测仍可执行。

## 12. P0 验收标准

满足以下条件后，QuantAgent 2.0 核心重构视为完成：

1. 用户可从网页上传符合数据契约的真实 OHLCV CSV。
2. 系统返回质量报告并持久化数据，重启服务后仍能加载。
3. 页面和 Agent 能识别 CSV 中任意合法股票代码，不再依赖固定枚举。
4. 用户可选择股票池、区间和参数完成因子分析及回测。
5. 回测结果包含指标、净值、回撤、换手和持仓，并保存数据版本引用。
6. Agent 不计算金融数值，只通过白名单工具获取结果。
7. 相同数据版本与参数可得到完全一致的回测结果。
8. 无效 CSV、未知股票、数据不足和模型调用失败均有明确错误。
9. `.env` 和 API Key 不出现在 Git 追踪文件、数据库或日志中。
10. 全部 P0 单元及集成测试通过。

## 13. 建议实施阶段

### 阶段一：数据底座

- 拆分领域层与基础设施层；
- 建立数据集、版本和股票池模型；
- 完成 CSV 导入、校验、Parquet 持久化及重启恢复。

### 阶段二：研究链路

- 重构因子和回测接口；
- 加入动态股票池、日期范围和数据版本；
- 改造回测持久化及历史结果查询。

### 阶段三：Agent 与前端

- 将 Agent 工具改为调用应用层用例；
- 移除硬编码股票枚举；
- 增加数据管理、因子分析、历史回测和风险展示。

### 阶段四：质量与交付

- 完成迁移脚本、自动化测试和性能检查；
- 更新 README、架构文档和面试说明；
- 使用真实样例数据完成端到端验收。

## 14. 待确认事项

以下选择不阻塞 P0 的需求文档，但应在技术设计开始前确认：

1. 首期主要面向 A 股，还是同时支持美股及其他市场；
2. 用户导入的数据默认采用前复权、后复权还是不复权；
3. 是否需要在首期接入具体行情供应商，还是先完成通用 CSV Provider；
4. 是否需要基准指数、行业分类和股票名称等扩展字段；
5. 历史回测是否需要支持删除、导出和多结果对比。
